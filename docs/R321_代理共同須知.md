# R3.21 遊戲開發代理共同須知（三款遊戲代理都要先讀）

1. 工作區只有 `/home/workspace/wordquest-web-dev-arc3`（git worktree，分支 `r321-arc3`）。**不要** `cd` 到 `/home/workspace/wordquest-web-dev`（那裏有另一個長任務在跑），**不要 git commit／push／stash**（總監統一提交），**不要執行 `tools/build_r37.py`**，**不要改** `gx_core.js`、`app/index.html`、`s*.js`、`s*.css`、街機任何檔案。你只可新增／修改：你那款的 `r37_src/<game>.js`、`r37_tests/t4x_*.py`、`r37_tests/gx_fixture/` 內以你的遊戲為名的檔案、`app/assets/r321/` 內只讀（美術由另一代理生成，可能尚未齊全；缺圖時遊戲必須用程式繪製的備用圖形照常運作，`GX.drawImg` 失敗會回傳 false）。
2. 先讀：`docs/R321_三款新遊戲設計書.md`（驗收標準 1–16 就是你的合格線）、`r37_src/gx_core.js`（整個檔，它提供音效／特效／鍵盤／學習邏輯／介面卡／外殼，你**必須**用它，不可自建音訊、粒子、結算、星級）、`r37_src/fps_game.js` 檔首 150 行與結算部分（看本專案遊戲的寫法與品質；**不要抄它的架構，也不要修改**）。
3. 遊戲寫成一個獨立檔案：IIFE，`globalThis.WQ37XX = { start(box, opts) -> {destroy(), pause(), resume()}, _debug getter, _step(n,dt), 及測試需要的 _cmd 之類 }`。`start` 內用 `GX.shell(box, opts, {id, music, onRestart, onResize, onResume})` 建外殼；用 `S.learn`（`GX.Learn`）決定出什麼題、判答案、回流、星級；用 `S.ui.how/preview/learn/ok/banner`、`S.finish({...})`、`S.openPause`；用 `S.fx` 做粒子浮字震屏；用 `S.sfx(名)` 發聲（名稱見 gx_core `R` 表，可用的才用）；用 `S.keys({...})` 接鍵盤，`GX.pad` 接觸控字母／數字盤；用 `S.later/S.every/S.on` 註冊計時器和監聽（destroy 會自動清）。**每個玩法動作都要有聲音與特效**。
4. 開發與測試用 `r37_tests/gx_fixture/lib.py`：`open_game(p, '<game>.js', 'WQ37XX', subject, w, s, difficulty, size=(390,844), touch=True)`，已備真實英文單元字表與 `WQ37Math` 題目（`OPTS.items` 就是 host 之後會傳的 item）。範例見 `r37_tests/gx_fixture/smoke.py`。英文 8 世界×10 關（每關 8 字，後兩個世界 12 字）；數學 6 世界（小一二…小六）×10 關。數學題目文字可以很長（應用題），也有小數與分數答案（`item.pad==='frac'`），題幹可能帶「＝？」。**題目內容由 host 決定，你的遊戲不得自己造題**（迷宮的「條件吃」關型除外，見該款說明）。
5. 測試：寫 `r37_tests/t4x_<game>.py`（本款的編號 td=t41、maze=t42、card=t43），用業務邏輯斷言（學習卡 ≥2 秒、回流、星級、答錯不能靠打怪過關、5 級難度參數真的改變行為、英文／數學兩個科目、三種尺寸版面無重疊截字、console 乾淨、destroy 後沒有殘留 canvas／計時器／音訊節點）。用確定性 `_step` 驅動遊戲邏輯，不要靠 sleep 碰運氣；測試必須能獨立重複跑出同一結果。
6. 視覺驗收（硬性）：390×844、360×640、844×390、1440×900 各截圖（英文＋數學），自己用 Read 看圖並放大檢查文字、對齊、遮擋、截字、按鈕大小、一屏放得下。效能：`cpu=4`（4 倍 CPU 限速）下量度幀時間，平均 < 8ms、最差 < 33ms，記錄在你的報告。
7. 學習深度不可妥協（設計書第 1–7 條）；若你發現某個玩法會令孩子「不看題目也能贏」，改設計，不要硬做。
8. 自己迭代到達標才回報；不要中途停下問問題（方向性疑問在報告裏列出，並採用最保守的做法）。如被中斷重啟，先檢查現有檔案與測試狀態再續做，不要重做已完成的。
9. 完成回報（精簡）：交付檔案、測試結果（數字）、截圖路徑（放 `r37_evidence/r321/<game>/`）、幀時間量度、已知缺口與你要我決定的事。誠實標明哪些項目未達標。
10. 現有設計語言：深藍紫底、金色重點、玻璃卡片、圓潤字體、可愛童話風角色；少說明文字，用圖示與動畫示範；動畫 ≤ 300ms 的 UI 轉場，遊戲內動畫自由但要尊重 `GX.reduced()`。
